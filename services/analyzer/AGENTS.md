# Analyzer Agent Instructions

## 1. 적용 범위와 담당

`services/analyzer/`에 적용하며 루트 `AGENTS.md`를 먼저 읽습니다.

D가 후보 추출·기존 provider·규칙/피싱 정황 분석·실제 근거 대조·선정 입력 처리·평가를 담당합니다. 기준은 계획서 5.0의 8·14·16.2장과 ADR 0004입니다. 입력 종류·우선순위는 V5-Q01에서 결정하며 STT/OCR을 자동 필수화하지 않습니다. 결정 전 공통 결과·오류·합성 텍스트 검사는 진행할 수 있습니다. Decisions API는 V5-Q06의 후속 검토로 현재 개발 범위 밖입니다. ID 조회·원본/보호 필드의 결정론 검증은 AI 없이 동작합니다.

## 2. 구현·계약 규칙

기존 카드 추출은 CardPaymentNoticeCandidate 회귀로 보존합니다. 새 유형 추출·분석은 V5-W1-C/D·V5-W5-C/D의 공통 모델·계약으로 확장합니다. 의심 원문·위치·네 단계 위험 결과는 발행 검증 상태와 별도로 유지합니다. 공통 모델을 임의로 복제하지 않습니다.

provider 기본값은 mock, OPENAI_MODEL 기본값은 gpt-6-luna입니다. provider 전용 객체는 Adapter 내부에 유지하고 모르는 필드는 null로 둡니다. 피싱 정황 설명을 발행 진위·Registry 판정으로 대체하지 않으며 원시 응답/민감값 로그를 금지합니다. 규칙/LLM 출처·근거 대조 실패·판단 보류를 구분하고 입력 속 명령을 실행하지 않습니다. 기존 어댑터·오류 처리를 재사용합니다.

## 3. 검증과 완료

Mock 단위·정상/변조·누락·refusal·timeout·incomplete·Schema 오류를 검사합니다. 실제 유료 API 검사는 명시적 opt-in이며 Mock replay를 실제 추출 정확도로 보고하지 않습니다. 합성 원본 60개의 24/36 분할·초기 목표는 계획서 14.2절을 따르고 선정된 입력만 평가합니다. 세 입력 180개를 자동 요구하지 않습니다.

## 4. 인계

C에게 후보 필드 변경과 합성 예시·기대 객체·평가 근거를 전달합니다. D의 전체 QA 역할이 다른 소유자의 테스트 경로를 무조건 수정할 권한을 뜻하지는 않습니다.
