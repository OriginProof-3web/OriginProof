## 7. 남은 문제

1. **5안 `/api` 프록시가 v3 를 넘기지 않음(가장 큼, U3 · 관련 U4·U5)**: `개발/collaboration-server.py` 가 실행하는 `…/OriginProof-w5-a-completion/apps/web/test/local-console-server.py`(5안 밖, 읽기만 함)는 `/api/v1/`·`/api/v2/`·`/api/health/` 만 넘기고 `/api/v3/`·DELETE 는 없고, 응답 헤더 중 `Retry-After` 를 버림. 그래서 그 서버로 열면 v3 요청은 404 → 화면은 "이 서버에는 분석 경로가 없어요"·v1 대체로 정직하게 보이지만 v3 흐름은 실제로 못 감. 프록시에 `/api/v3/`(GET·POST·DELETE)와 `Retry-After` 전달을 더하거나, 다른 같은 출처 프록시가 필요 — 5안 밖 파일이라 손대지 않음(대표·본부 결정 필요). `연결 주소 바꾸기`로 `http://127.0.0.1:<포트>` 직접 연결도 되지만 서버 `browser_origins`(Origin 검사)·CORS 허용이 있어야 함
2. 서버 기본값(U9·U6·U7, Registry 단계는 8-0-2 R1~R5): `API_WALLET_TEXT_INPUT_ENABLED=false` 면 `/v3/inputs` 는 409 `INPUT_SUPPORT_UNDECIDED`(화면: "서버가 입력 받기를 아직 켜지 않았어요."). Registry 미주입이면 지갑 기능 503 `WALLET_REGISTRY_UNAVAILABLE`, 분석기 미주입이면 `FAILED / ANALYZER_UNAVAILABLE` — 모두 그대로 보여 줌
3. 계약 "응답의 원본 bytes·보호 hash·domain/message 를 재계산해 지갑에 표시"의 브라우저 재계산(keccak)은 안 함. 지갑이 EIP-712 내용을 보여 주는 것에 기댐
4. 지갑 거래 보내기는 사람이 해시를 붙여 넣는 방식(자리 없음 11)
5. 응답 유실(네트워크·시간 초과) 뒤 다시 누르면 같은 request_id·같은 본문으로 한 번 더 물음(서버가 기존 결과를 돌려주는 계약 동작). v3 에는 request_id 로 작업을 찾는 목록 경로가 없어 web-2안 `session.js` 의 목록 조회 복구는 v3 에 못 씀
6. 가져온 시험 중 web-2안 화면 전용 5건은 건너뜀(5안 화면 시험은 `시험/op5_connect.test.js` 로 대신)
7. 실제 브라우저 확인은 본부 실측 요청(9절)
