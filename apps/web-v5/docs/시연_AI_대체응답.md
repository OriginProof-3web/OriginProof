# 시연용 AI 지연 대체 응답 (기본 꺼짐)

5차 멘토 피드백: 시연은 실제 AI로 하되, AI API가 늦으면 실패 화면 대신 준비된 응답으로 바로 넘어간다.
저장소 규칙("미구현 동작을 성공 응답으로 대체하지 않는다")에 맞춰 **기본은 꺼짐**이고, 켜도 화면에 **'준비된 시연 응답 · 실제 AI 결과 아님'**이 보인다.

## 켜는 법

실서버 모드 주소에 쿼리를 붙인다. 그 페이지를 여는 동안만 켜지고 저장되지 않는다.

```
business.html?mode=api&demo_ai_fallback=5
```

| 값 | 결과 |
| --- | --- |
| 쿼리 없음 · `0` · 숫자가 아닌 값(`abc`, `5.5`, `-5`) | 꺼짐(기존 동작 그대로) |
| 값 없음(`?demo_ai_fallback`) | 5초 |
| `1`~`2` / `3`~`10` / `11` 이상 | 3초 / 그 값 / 10초 |

- `?demo=장면` 재현(가짜 응답)에서는 쓰지 않는다.
- 켜지면 입력칸 아래 안내 줄에 `시연 AI 대체 N초 켜짐(준비된 시연 응답)`이 붙는다.

## 동작

1. 평소처럼 `/v3/inputs` → `/v3/analyses` → `GET /v3/analyses/{id}` 폴링을 시작한다.
2. N초 안에 분석이 끝나지 않고, 입력 글이 아래 예시 문자 3개 중 하나와 같을 때만(공백 차이 무시) AI 칸에 준비 응답을 보여 준다.

| 시나리오(`페이지/data/sample_data.js`) | 준비 응답 |
| --- | --- |
| `normal` 정상 안내(85,000원) | 뚜렷한 위험 신호 없음 |
| `tamper` 금액 1원 변조(85,001원) | 뚜렷한 위험 신호 없음 + "금액 변조는 블록체인 기록 대조(원본 일치 칸)가 판정" |
| `unregistered` 원격 지원 사칭 | 고위험: "원격 지원 앱을 설치해 주세요" |

3. 준비 응답을 보여 준 뒤에도 폴링은 계속한다. 실제 작업이 `pollLimit`(기본 200초) 안에 끝나면(완료·실패·취소·만료) 아래에 실제 결과 답을 새로 그리고, 위 AI 칸에 "→ 아래 실제 AI 결과로 교체됐어요"를 붙인다. 끝나지 않으면 "준비된 시연 응답 그대로(실제 AI 결과 아님)" 말풍선을 남긴다.
4. 사용자가 분석을 지우면 기존처럼 늦은 응답을 버린다(교체하지 않음).

## 화면 표시

- AI 칸 상태: `준비된 시연 응답 · 위험 신호` 등, 본문 맨 앞 `[준비된 시연 응답 · 실제 AI 결과 아님]`
- AI 구역 제목표: `준비된 시연 응답 · 실제 AI 결과 아님`, 근거 줄 출처도 같은 글
- 직원 칩(AI): `[준비된 시연 응답] …`
- 답 라벨·'자세히': 시나리오 id·대체 기준 초·`DEMO_PREPARED_RESPONSE_NOT_AI_RESULT`, 기록에 "준비된 시연 응답 표시"·"실제 AI 결과로 교체" 줄
- 발행 검증 3칸(공식 발행·원본 일치·현재 상태)과 결론은 서버 응답 그대로이며 이 기능이 바꾸지 않는다.

## 한계

- 예시 문자와 글이 같을 때만 동작한다. 실제 기관이 새로 발행한 문자(다른 Proof ID)는 대상이 아니다. 시연 프리셋 단추는 실서버 모드에서 `unregistered`만 보내므로, 정상·변조는 예시 문자를 입력칸에 붙여 넣어야 한다.
- 문서 사진 입력은 대상이 아니다.
- 준비 응답은 미리 쓴 합성 설명이며 모델 평가 결과가 아니다. 분석기 응답 속도(temperature 등)는 D 분석기 영역이라 다루지 않았다.
- 시험은 가짜 fetch·가짜 시계(화면 시험 1건은 실제 3초 대기)로만 확인했다. 실서버·실제 브라우저에서는 확인하지 않았다.

