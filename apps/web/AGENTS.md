# Web Agent Instructions

## 1. 적용 범위와 담당

`apps/web/`에 적용하며 루트 `AGENTS.md`를 먼저 읽습니다.

A가 사용자·발행기관·운영자 화면, UX·접근성·브라우저 동선을 담당합니다. MVP Gate는 완료되었으므로 화면 착수의 대기 조건으로 사용하지 않습니다.

## 2. 구현·계약 규칙

승인된 모델/API의 생성 타입을 사용하고 API가 없으면 합의된 예시·mock으로 화면 검사를 진행합니다. UI에서 진위·권한을 독자 판정하지 않습니다. 기관 지갑에 서명을 요청하되 앱은 개인키/복구 구문을 수집·저장하지 않습니다. 원본 hash와 보호 필드·도메인을 확인하고 주소/네트워크 변경·서명 거절을 처리합니다. API 연결 전 화면 성공을 실제 발행/폐기/consume 성공으로 기록하지 않습니다.

검증 상태와 lifecycle, ID 조회와 내용 비교를 구분합니다. VERIFIED라도 만료·폐기·소비 상태이면 사용 가능이라고 표시하지 않습니다. 로그인 만료·권한 거부·대기·실패·재시도·빈 결과를 제공하고 조회가 consume을 호출하지 않게 합니다. 신규 QR/링크에는 documentId와 버전을 식별하는 공개 경로를 넣고 실제 조회 버전을 표시합니다. 기존 Proof ID 링크는 구버전 경로로 유지하며 민감정보를 URL에 넣지 않습니다. 공동승인 진행·단독 정지/공동 복구·다음 버전/대체는 UI/UX 1.1의 UX11~14를 따릅니다. 미선정 입력과 Decisions 기능을 활성 화면으로 추가하지 않습니다.

## 3. 검증과 완료

기존 package scripts의 lint·typecheck·component·build와 관련 Playwright E2E를 실행합니다. 키보드·모바일/데스크톱·오류 문구를 검사하고 실제 API·새 사용자 세션에서 핵심 흐름을 확인합니다. 휴대폰 QR는 실제 LAN 환경에서 검증한 경우만 성공으로 기록합니다.

## 4. 인계

C에게 route·입력·응답·필드 오류·생성 타입 불일치를 전달하고 D와 실패·접근성을 확인합니다. 각 작업의 실제 API 연결 전까지는 독립 화면 검사의 완료만 보고합니다.
