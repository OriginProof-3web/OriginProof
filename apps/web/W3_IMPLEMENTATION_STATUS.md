# W3 웹 구현 상태

기준: `origin/integration@3295a71c10a1a99c523d3cfefde91b5737b737ac`; 계획서 v3.0, ADR 0001.

## 이번 준비 PR에 포함된 것

- W3-A1: ADR 0001의 두 Proof 유형에 맞춘 화면 필드, 양의 정수 금액/문서 버전, 통화 형식과 만료 시각의 로컬 입력 검증.
- W3-A2: 자기 기관 발행 기록이 아직 조회되지 않았음을 나타내는 빈 상태 자리.
- W3-A3: 공개 ID 조회와 인증된 필드 비교를 분리한 화면 틀. 비교는 발행기관 담당자 또는 지정 수신자로 제한하고 조회가 consume을 실행하지 않는다는 안내.
- 검사는 synthetic 입력/mock만 사용합니다. 화면은 요청 미전송·조회 미실행·lifecycle 미확인을 표시합니다. 실제 발행 성공이나 검증 결과는 만들지 않습니다.

## 실제 W3 연결을 아직 완료하지 않은 이유

1. `origin/integration`에 W1-C3의 생성된 v2 TypeScript 모델과 Golden Fixture가 없습니다. ADR은 정책 필드를 정하지만 웹이 직접 API wire type을 정의하거나 생성 타입을 대신할 수 없습니다.
2. W3-C1 발행 endpoint·입출력·필드 오류·요청 중복 처리 계약이 없습니다. 수신자 선택 API도 확인되지 않았습니다.
3. W3-C2 자기 기관 목록/상세와 공개 ID 조회 응답 모델, 공개 필드 경계가 없습니다.
4. W3-C3 검증 API의 scope/status/lifecycle/checks/reason enum이 생성 모델로 제공되지 않았습니다. 따라서 금액 변조·문서번호 변조 결과를 웹이 자체 판정할 수 없습니다.
5. W3의 실제 시나리오는 W2-C3의 보호된 서명기·키 등록 상태와 W3-B1 Reader 상태 확인에도 의존합니다. PR #23 및 #26은 확인 시점에 미병합이므로 실제 연결로 사용하지 않았습니다.

따라서 화면 준비는 별도이며, W3 실제 발행·저장·목록·QR·다른 세션 재조회·정상/변조 판정은 미완료입니다. C/B가 위 계약과 생성 타입을 단계 branch에 반영한 뒤 그 SHA에서 연결 검사와 E2E를 추가해야 합니다. 확정된 ADR 정책을 다시 미결정으로 취급하지 않습니다.
