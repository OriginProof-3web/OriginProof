작성일: 2026-10-09 · 개정일: 2026-10-18 · 목록 버전: **0.3**

[최신 개발 계획서](development_plan.md) 16.2절 V5-Q01~09를 [산출물 상세안 0.5](final_deliverables_draft.md) D01~D08과 연결합니다. 적용 결정은 [ADR 0004](adr/0004-v5-governance-wallet-versioning.md), 화면은 [UI/UX 1.1](ui_ux_design.md)을 따릅니다. 목록 작성·계약 선택·구현·실제 연결·제출 완료는 별도입니다.

후보 제품·네트워크 규칙·비용은 실제 선택 시 최신 근거로 확인합니다. 로컬/Mock 성공으로 공개 배포나 실제 모델 평가 완료를 대신하지 않습니다.

## 5. 유지하는 결정과 이전 번호의 관계

- 공동승인·기관 지갑·버전 관리와 기존 Python/Next.js 구성 재사용은 ADR 0004의 적용 방향입니다.
- 보관·권한·삭제·데모 이메일 코드 기본값은 계획서 9장을 유지합니다. L10은 그 정책을 실제 DB/구자료에 적용하는 방법입니다.
- 평가 원본 60개·24/36 분할·초기 지표는 계획서 14.2절을 사용하되 선정된 입력만 제작·평가합니다. 미선정 세 입력 180개를 요구하지 않습니다.
- 이전 Q01 행사→V5-Q07, Q02 공개 체인→V5-Q04, Q03 입력→V5-Q01, Q04 모델→V5-Q05, Q05 보관→유지 정책/V5-Q09, Q06 계약→V5-Q03, Q07 이메일→유지 정책으로 연결합니다.
- 기존 “입력 지원 확정” 기록은 최신 답변으로 대체됐습니다. 선택되지 않은 형식·지갑 라이브러리·새 schema 번호·모델·예산을 이 목록에서 임의로 확정하지 않습니다.

## 6. 상태 갱신과 결정 기록
