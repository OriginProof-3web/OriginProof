# 개인 기여와 포트폴리오 기록

개발 중 확인한 사실을 남겨 팀원별 W1~W7의 역할과 결과를 설명할 수 있게 합니다. PR은 작업의 상세 근거, 개인 단계 기록은 PR을 모은 요약, 단계 완료 PR과 고정된 `phase/Wn`은 팀 전체 결과입니다. 같은 설명·로그를 여러 파일에 복사하지 않고 원본 링크를 연결합니다.

## 기록할 시점과 위치

| 시점 | 담당과 기록 위치 | 남길 내용 |
| --- | --- | --- |
| 착수 | 작업 담당자, 이슈 또는 PR 초안 | 역할·GitHub 계정·단계·작업 ID·문제·완료 기준·선행 작업·시작 SHA. 계획과 실제 완료를 구분합니다. |
| 개발 중 | 담당 에이전트, 이슈/PR 갱신 | 실제 선택한 설계와 이유, 중요한 실패·원인·수정, 계약/ADR 변경, 협업 인계. 단순 실행 로그 전체 대신 판단과 재현 근거를 남깁니다. |
| PR 제출·수정 | 작성자, [PR 템플릿](../../.github/pull_request_template.md) | 개인별 기여, 변경 전후 동작, 검증 명령·환경·SHA·기대/실제 결과, 잔여 한계. 리뷰로 바뀐 결정도 기록합니다. |
| 담당 단계 작업 마무리 | 각 담당자, `docs/portfolio/Wn-A.md`~`Wn-D.md` | 실제 작업이 생긴 파일만 만들고 아래 양식으로 갱신합니다. 작업 PR의 근거를 연결하며 아직 막힌 항목이 있으면 부분 완료로 표시합니다. |
| 단계 전체 완료 | 단계 통합 담당자, `phase/Wn → integration` PR | A~D 개인 기록 4개를 연결하고 최종 단계 SHA·통합 검증·미완료 여부를 확인합니다. 각 담당자와 리뷰어가 개인 기여와 결과의 사실관계를 확인합니다. |

여러 단계를 묶어 개발해도 PR과 개인 기록은 단계별로 나눕니다. 단계 기록도 동결 전에 해당 `phase/Wn`으로 문서 PR을 통해 반영합니다. 테스트한 코드 SHA와 기록 문서를 추가한 최종 SHA가 다르면 둘을 구분하며, 단계 전체 최종 SHA는 단계 완료 PR에 기록합니다. 단계 브랜치를 고정한 뒤 링크·설명을 보충할 때는 별도 문서 PR로 `integration`에 반영하고 원래 단계 SHA를 보존합니다.

## PR에 남길 상세 근거

- **문제와 범위:** 어떤 사용자 동작에서 무엇이 부족했는지, 이번에 바꾼 범위와 제외한 범위, 기존 구현·팀원 작업을 재사용한 부분을 적습니다.
- **개인별 기여:** 설계·구현·테스트·리뷰·장애 분석·통합·문서 역할을 실제 담당자별로 구분하고 파일/커밋/리뷰/이슈 근거를 연결합니다. PR 작성자나 병합자라는 이유만으로 전체 작업의 구현자로 기록하지 않습니다.
- **기술적 판단:** 주요 선택, 실제 검토한 대안, 선택 이유와 비용·제약을 적습니다. 공유 계약·보안·되돌리기 어려운 변경은 기존 ADR을 연결합니다. 대안 검토가 없었으면 만들지 않고 해당 없음으로 적습니다.
- **문제 해결:** 중요한 실패는 증상 → 재현 조건 → 원인 → 해결 → 재발 방지 검사 순서로 남깁니다. 실패한 시도도 결정에 영향을 준 경우만 기록합니다.
- **검증과 결과:** 정상·실패 사례, 실행 명령, 실제 결과, 코드 SHA, 환경·데이터 버전, Mock/실제 API/로컬 EVM 여부를 함께 적습니다. 미실행·실패·통과를 구분하고 CI run 링크도 연결합니다.
- **성과와 한계:** 전후 동작·화면·재현 결과를 남깁니다. 성능 수치는 같은 환경·데이터·명령·측정 횟수의 전후 근거가 있을 때만 쓰며 미측정 수치나 개선율을 만들지 않습니다. 수치가 없으면 확인한 동작 변화로 설명합니다.
- **협업과 AI 사용:** 누가 계약·구현을 제공했는지, 본인이 연결하거나 검토한 부분, AI 도구가 초안/구현/테스트에 기여한 범위와 사람이 결정·수정·검증한 내용을 구분합니다. 알 수 없는 기여 비율이나 AI 사용 비율을 추정하지 않습니다.
- **남은 일:** 미완료 항목·영향·다음 담당자·이슈를 연결합니다. 실험·Mock 성공과 실제 통합 완료를 구분합니다.

커밋 개수나 코드 줄 수를 개인 기여 비율로 환산하지 않습니다. 공동 작업은 각자의 책임과 근거를 나누고 확인되지 않은 단독 기여를 주장하지 않습니다. 인증된 GitHub 계정과 Git 작성자 설정이 실제 작업자를 나타내는지 확인하되, 에이전트가 다른 팀원으로 가장하거나 다른 사람의 작성자 정보를 임의로 설정하지 않습니다. 설정이 맞지 않으면 담당자에게 알리고 기여 표에 실제 역할을 명시합니다.

## 증거 보관과 공개 범위

작은 합성 데이터 화면·다이어그램은 `docs/portfolio/assets/Wn/` 등 관련 문서 경로에 두고 상대 링크로 연결할 수 있습니다. 영상·큰 로그는 팀이 접근 가능한 승인된 저장 위치를 사용하고 링크·촬영/실행 SHA·환경을 기록합니다. 중요한 CI 결과는 실행 링크와 명령·결과 요약을 저장소에도 남겨 임시 artifact가 만료되어도 결론을 확인할 수 있게 합니다. 코드 근거는 가능하면 커밋 SHA가 고정된 링크를 사용합니다.

개인 컴퓨터의 절대 경로·에이전트 대화만을 유일한 증거로 사용하지 않습니다. 토큰·비밀번호·개인키·실제 개인정보·원문 문서는 기록에 넣지 않고 합성 데이터와 마스킹된 증거를 사용합니다. 기록 추가가 저장소 공개나 외부 업로드 허가를 뜻하지 않습니다. 공개 포트폴리오로 옮길 때는 팀의 공개 가능 범위를 확인하고, 비공개 PR 링크만으로 설명을 대신하지 않도록 허용된 요약·이미지를 준비합니다.

## 개인별 단계 기록 양식

아래 양식을 실제 작업이 발생한 `Wn-역할.md` 파일에 사용합니다. 예를 들어 사용자님의 W1 기록은 `W1-C.md`입니다. 미래 단계 파일이나 완료 내역을 미리 채우지 않습니다. 필요 없는 항목은 해당 없음과 이유를 적고, 자세한 내용은 원본 PR/ADR을 연결합니다.

```markdown
# Wn / 역할 / 이름 — 개인 개발 기록

- GitHub 계정:
- 실제 작업 기간: YYYY-MM-DD ~ YYYY-MM-DD (Wn은 달력 주차가 아님)
- 상태: 진행 중 / 부분 완료 / 검증 완료
- 작업 ID·이슈 / 작업 묶음:
- 단계 브랜치 / 시작 기준 SHA / 검증한 코드 SHA:
- 단계 완료 PR: 생성 전이면 미생성; 생성 후 링크 갱신

## 목표와 실제 결과
문제·사용자 영향, 맡은 범위, 실제 구현 전후 동작과 완료/미완료를 적습니다.

## 개인 기여와 협업
| 작업 ID | 본인이 수행한 일 | 재사용·다른 담당자 기여 | 근거 PR·커밋·리뷰 | 상태 |
| --- | --- | --- | --- | --- |

## 주요 결정과 문제 해결
- 선택과 이유·실제 검토한 대안·제약 / ADR:
- 증상·재현·원인·해결·재검증 / 이슈 또는 PR:
- 리뷰에서 받은 피드백과 반영:

## 검증·시연 증거
| 사례·명령 | 기대 결과 | 실제 결과·통과/실패/미실행 | SHA·환경·데이터 | 증거 링크 |
| --- | --- | --- | --- | --- |
- 전후 화면·영상·다이어그램 및 실행 방법:
- 측정 성과와 측정 조건 또는 미측정:

## AI 활용과 본인의 판단
- 사용 도구와 활용 범위:
- 본인이 설계·검토·수정·검증한 내용:

## 배운 점·한계·다음 작업
- 새로 이해한 내용과 근거가 된 결정/실패:
- 남은 제약·미완료·다음 담당자와 이슈:
- 포트폴리오 설명 초안: 문제 → 본인 역할·판단 → 구현 → 확인한 결과

## 사실 확인
- 본인 확인: 계정 / 날짜 / 확인 내용
- 작성자 외 리뷰어: 리뷰 링크 / 확인한 기여·검증 범위 / 남은 이견
```

작성자 외 확인은 실제 리뷰 결과로만 채웁니다. 에이전트가 다른 사람의 확인을 대신 작성하거나 요청 없이 팀원에게 메시지를 보내지 않습니다. 개발 담당 에이전트는 작업 종료 전 PR과 개인 기록을 갱신하고, 누락된 증거·리뷰·차단 사항을 완료 보고에 남깁니다. 이 규칙은 에이전트 작업 절차이며 별도 백그라운드 수집기나 강제 CI 검사는 아닙니다.
