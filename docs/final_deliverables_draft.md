# 찐품명품 · OriginProof 5.0 — 최종 산출물 구체화안

작성일: 2026-10-08 · 개정일: 2026-10-13 · 상세안 버전: **0.5** · 기준: 개발 계획서 **5.0**

상태: **산출물·완료 기준 문서 반영 / 제품 구현·실제 연결·팀 리뷰·평가·제출 완료와 별개**입니다. [개발 계획서](development_plan.md)가 범위·일정·검사의 기준본이고, [ADR 0004](adr/0004-v5-governance-wallet-versioning.md)가 결정과 전환을, [UI/UX 1.1](ui_ux_design.md)이 화면을, [후속 결정 목록](final_deliverables_pending_decisions.md)이 미정 선택과 계약 검토를 관리합니다.

기존 D01~D08 구성을 유지합니다. 입력 종류·우선순위·사용자 원본 업로드 형식은 회의 후 확정하고 Decisions API는 현재 개발 범위 밖입니다. 기존 0.4의 세 입력 필수·운영자 단독 활성화·서버 기관 서명·신규 안내의 새 ID 재발행 가정을 아래 기준으로 대체합니다.

결과 순서는 한 줄 안내 → AI/발행 결과 → 근거 → 비교 범위/현재 상태 → 행동 → 보관입니다. AI 낮음+변조·정상 QR 복사·미등록·모델/RPC 개별 실패를 구분합니다. 제한된 기존 원문은 버전별 기관/수신자 권한을 유지하고 오류에 기대값을 노출하지 않습니다.

완료에는 실제 API/DB/체인과 선정 입력의 분석 연결, 다른 사용자 세션·새로고침·뒤로가기·timeout·만료·삭제, 키보드/320px에서의 핵심 동선 검사가 필요합니다. 미선정 음성/OCR과 Decisions 추천 화면은 완료 조건에 포함하지 않습니다.

최종 보호 필드·원본 생성 방식·서명 타입은 V5-Q03에서 고정합니다. 납부 안내의 계좌·금액·기한과 공식 행동 링크(제공 시)를 보호하고 UI 표시가 서명 원본을 조용히 바꾸지 않게 합니다. 키/네트워크/내용이 바뀌면 다시 확인·서명합니다.

완료는 신규 기관 신청부터 서로 다른 승인자 2명의 활성화, 기관 직접 서명·발행·다음 버전·철회까지 실제 브라우저로 재현하는 것입니다. 자기 승인·타 기관·구키 새 발행·동시 다음 버전·서명 재전송은 거부되어야 합니다. 기존 요청형 consume은 레거시 회귀로 유지하고 공개 안내에는 추가하지 않습니다.

## 4. D03 — 운영·공동승인 웹

O01/O02는 신청 근거·키 증명·기관/공개 주소·메타데이터 hash·작업·만료를 묶은 고정 제안과 승인자별 진행을 표시합니다. 0/2·1/2·2/2와 실제 체인 확정은 구분합니다. 중복·만료·변경된 제안은 거부하고 두 번째 승인 실행 뒤 체인 재조회로 활성화를 확인합니다.

O03/O04는 기관/키·변경 이력, 승인자 1명 또는 기관 활성 키의 긴급 정지와 2-of-3 재활성화를 제공합니다. 운영자 웹 계정만으로 체인 권한을 얻지 않으며 개인키·제한 원문 조회 기능을 관리 화면에 추가하지 않습니다. 개발 담당 A/B/C와 승인 지갑을 혼동하지 않도록 승인자 1/2/3으로 표시합니다.

완료에는 1명으로 활성화/재활성화 불가, 서로 다른 2명 승인, 단독 정지 후 발행 거부, 소유 기관/승인자 권한·만료·중복 검사와 오류/재조회 UX가 필요합니다. 같은 팀의 세 지갑 시연을 독립 기관 운영 완료로 표현하지 않습니다.

| 문서·서명 API | 원본/보호 필드·documentId/version·초안·서명 제출·철회·키/상태 검사 |

[서명 명세](signing_spec.md)의 신규 부분은 구현 전 계약입니다. 필드명·타입·최종 schema·정확한 endpoint는 C/B가 실제 소비자와 맞춰 고정하고 예시·오류·교차 Golden을 제공합니다. 기존 URL과 PDF의 제안 URL을 중복 구현하지 않습니다. AI enum은 같은 의미의 이전 초안 이름을 혼합하지 않고 원본 모델로 고정합니다.

완료에는 정상/거부·동시성·실제 PostgreSQL/Adapter·저장 실패·서명/원본 불변·새 migration·복구·소비자 연결과 v1/v2 회귀가 필요합니다. 문서에 예정 경로가 있다는 이유로 현재 호출 가능하다고 표시하지 않습니다.

## 6. D05 — 블록체인·배포·별도 검증

| 구성 | 제공할 코드·계약·완료 증거 |
| --- | --- |
| 신규 Registry | 2-of-3·키 증명·정지/재활성화, 기관 EIP-712·소유권·nonce/deadline·원자적 버전 |
| ABI·Adapter·indexer | 신규 이벤트·현재 상태 직접 조회·projection/체인 불일치·UNKNOWN/receipt 복구 |
| 배포 목록 | 로컬/공개, chain ID·계약 주소/버전·배포 시작 block/hash·코드 SHA·ABI·확정 기준 |
| 별도 검증 자료 | 허용된 서명 원본·hash/서명 규칙·ABI/배포 식별·서비스 API 없이 재현할 절차 |
| 과거 호환 | 이전 배포·v1/v2 규칙·읽기/consume 회귀, 신규 배포와 구분 |

배포자 단독 우회·업그레이드 우회가 없는 신규 통합 Registry를 별도 배포합니다. chain ID만 같다는 이유로 과거 주소·DB·이벤트를 새 배포와 섞지 않습니다. 네트워크·비용·확정/reorg 규칙은 V5-Q04에서 결정합니다. 서버 기관키 백업은 레거시 한정이며 신규 기관키는 기관 지갑이 보유합니다.

완료 증거에는 정상 발행·서명/원본 변조·다른 기관/도메인·동시 버전·철회·정지·재시작·RPC/reorg와 서비스 밖 대조 결과가 필요합니다. 공개 목표 미달성은 그대로 기록하고 로컬 성공으로 전체 목표를 채우지 않습니다. DB에서 삭제된 원본을 hash로 복구할 수 없음을 설명합니다.

## 7. D06 — AI·보고서·평가

| 구성 | 제공할 결과·완료 증거 |
| --- | --- |
| 선정 입력 처리 | 실제 변환 결과와 해당 문장/페이지·영역/시간 위치, 저품질·누락·미지원 처리 |
| 분석 | 사칭·송금/계좌 변경·민감정보 요구·링크/앱 설치·확인 방해를 문맥/행동으로 설명 |
| 근거 | 실제 입력/변환 텍스트와 인용을 대조, 허구 근거 차단·누락/위치 정확도 평가 |
| 보고서 | 네 단계 위험 의미·이유·행동·규칙/LLM 출처·한계·독립 발행/비교/현재 상태 |
| 실패 | 삽입 지시·refusal·timeout·Schema 오류·빈/손상 입력·늦은 결과·명시적 보류 |
| 평가 | 데이터/정답·검토자·분할·모델/프롬프트·실측 품질/지연/비용·실패/한계 |

기존 provider·추출·오류 처리를 재사용합니다. AI는 발행·승인·지갑·DB 변경 권한을 갖지 않습니다. 규칙 fallback은 규칙 결과로 표시하며 실제 모델 성공으로 세지 않습니다. AI 실패와 RPC 실패는 각각 보고합니다.

합성 원본 60개(수준별 15개), 개발 24개/보류 평가 36개 분할을 유지하고 선정 입력만 변환합니다. 같은 사례의 변형은 같은 집합에 배정합니다. 선정 입력별 최소 4개 실패 사례와 공통 provider/삽입 지시 사례를 포함합니다. 세 입력 180개를 확정 수량으로 쓰지 않습니다.

계획서 14.2절의 초기 목표·측정 정의를 사용합니다. macro-F1 0.80, HIGH recall 0.90, 판독 가능한 보호 필드 일치율 0.95는 측정 전 목표이며 실측값으로 표현하지 않습니다. 표시할 인용은 원문 대조를 통과해야 합니다. 보류·실패율·분모·confusion matrix·근거 누락/위치 정확도를 함께 기록하고 실측 후 합격선을 조용히 바꾸지 않습니다.

입력 선정은 V5-Q01, 실제 모델/유료 평가·전송 설정은 V5-Q05입니다. Decisions API는 V5-Q06의 후속 UX 아이디어이며 D06 필수 구현·성능 목표에 넣지 않습니다.

## 8. D07 — 실행·복구·검증 패키지

| 제공물 | 최소 내용 |
| --- | --- |
| 실행 안내 | 환경/lockfile → 설정 공급 → DB·체인·가상 자료 준비 → 기동/접속 → 정상 확인 → 종료 |
| 복구 안내 | DB/체인/manifest 식별, 같은 배포 재시작·새 배포 구분, 백업/복원·migration·UNKNOWN·원본 삭제 한계 |
| 수용 결과 | V5-F01~21별 입력·기대/실제·PASS/FAIL/NOT_RUN·SHA·환경·실행자·증거 |
| 독립 재현 | 다른 노트북/깨끗한 환경 설치부터 전체 흐름·차이/실패·해결 |
| RC·리허설 | 코드/배포/데이터/문서 버전, 동일 후보 전체 리허설 3회·대체 장비/영상 전환 |
| 기여/인계 | 담당·재사용/본인 변경·리뷰·실행 범위·미완료·후속 작업 |

실행 명령은 실제 RC의 Makefile/package scripts에서 확인합니다. 예전 MVP 명령이 새 기능 전체를 검사한다고 쓰지 않습니다. mock/로컬 체인/공개 체인·작성자 검사/독립 검사·opt-in skip을 구분합니다. G07 등 기존 실패는 최종 후보에서 원인/수정/재검사 근거가 있어야 해결로 기록합니다.

## 9. D08 — 발표·영상·제출

| 제공물 | 최소 내용·확인 |
| --- | --- |
| 발표 원본/제출본 | 실제 문제·서비스 흐름·블록체인 필요성·공동 권한·AI 역할·구현/한계·실측값 |
| 전체 시연 영상 | 가상 인증/두 승인→기관 서명→발행/QR/비교→변조·버전·철회·키 사고→선정 입력·장애/별도 검증 |
| 시연 대본 | 역할별 세션·지갑·장비·실제 접속 경로·장면별 시간·장애 대체/예비 영상 |
| 제출 목록 | D01~08별 실제 파일/URL·설명·버전·담당·공개/제한·파일 열기/접근 확인 |

행사 기한·채널·길이·해상도·자막·공개 범위는 V5-Q07의 외부 조건을 확인한 뒤 정합니다. 발표가 짧아도 필수 기능은 전체 영상·수용 기록으로 확인할 수 있어야 합니다. 편집 영상·로컬 데모·미선정 입력·Decisions 후속 검토를 실제 동작/공개 배포 성공으로 소개하지 않습니다.

PC 로컬 브라우저를 기본으로 준비하고 다른 기기 QR을 선택하면 LAN 주소·방화벽·실제 접근 근거를 추가합니다. RC가 바뀌면 영향 검사와 리허설 증거를 새 버전에 맞춥니다. 인터넷 호스팅·외부 제출은 문서 작성으로 실행한 것이 아닙니다.

## 10. 공통 UX·오류·보관 기준

15개 템플릿과 시각/모바일/접근성은 UI/UX 1.1을 따릅니다. 가짜 진행률·임의 피싱 확률·색상만의 상태 표시를 사용하지 않습니다. 지갑 거절·주소/네트워크 변경·서명 만료와 전송 후 UNKNOWN을 구분합니다. 미확인 작업은 기존 상태부터 확인합니다.

보관 기본값은 계획서 9장을 사용합니다. 미선택 원본은 처리 종료 후 삭제, 일시 결과는 종료 후 최대 10분, 선택 보고서는 종료 후 7일, 선택 원본은 수락 후 7일입니다. 기관 발행 원본·서명은 버전별 만료 후 30일까지 별도 보존하며 사용자 분석 삭제로 지우지 않습니다. 접근 차단·실패 잔여물·재시작 정리·늦은 결과 재저장을 검사합니다.

검색/통계·원문 diff·마스킹 보고서 파일·추가 운영 화면은 여유 시 보강입니다. 기존 v1/v2 읽기·서명·consume 회귀를 유지하며 필요 없는 신규 편의 기능으로 일정을 늘리지 않습니다.

## 13. 최종 인계 목록과 완료 판정

각 D01~D08 인계 행에는 실제 파일/접속 URL, 코드 SHA, 문서/schema/ABI/배포 버전, 담당/검토자, 확인 시각, 검사/실패 근거, 공개/제한 구분, 남은 항목을 기록합니다. 실제 경로가 준비되지 않았으면 미준비로 표시하고 계정 전달은 보호된 경로를 사용합니다.

산출물 완료에는 구현 존재·계약 일치·정상/거부/실패 검사·실제 연결·관련 작성자 외 검토·정확한 버전 인계가 필요합니다. 프로젝트 완료는 기존 성과를 포함한 7주 작업·V5-F01~21·구버전 회귀·다른 환경 재현·동일 RC 리허설 3회·D01~D08을 함께 확인합니다. 공개 목표 미달성과 실제 모델 미평가를 로컬/mock 결과로 채우지 않습니다.

이번 0.5 개정은 문서 기준을 동기화한 작업입니다. 제품 코드·DB·배포·기능 검사·팀원 리뷰·행사 제출의 완료 상태는 바꾸지 않았습니다.
