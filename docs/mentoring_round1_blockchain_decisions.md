## 1. 블록체인이 왜 필요하고 무엇을 저장할 것인가

### 검증 범위와 기관의 참여 이유

검증할 사실은 **“해당 기관이 이 내용의 납부 요청을 실제로 발행했다”**입니다. 발행 출처, 보호된 내용의 일치 여부, 현재 유효성을 확인합니다. 납부 의무의 정당성과 금액의 업무상 정확성은 발행기관이 책임집니다.

기관·기업은 **자사 명의를 사칭하거나 납부 계좌를 바꾼 요청을 수신자가 구별할 수 있도록 공식 확인 수단을 제공하기 위해** 참여합니다. 이는 제안하는 도입 가치이며 실제 도입 수요를 확인한 결과는 아닙니다.

### 블록체인의 필요성

발행 증거와 상태 변경 이력을 **중앙 DB 밖의 공개 체인에도 기록하여, 저희 서버의 설명에만 의존하지 않고 확인할 수 있게 하는 것**이 목적입니다.

- 평소에는 사용자가 OriginProof 서비스를 통해 검증 결과를 받습니다.
- 필요하면 권한 있는 수신자·검증자가 **저희 서버를 거치지 않고 별도 검증**할 수 있도록 합니다.
- 별도 검증에 필요한 **기관이 서명한 원본 데이터·전자서명·검증 규칙**을 권한 있는 수신자에게 제공합니다. 체인의 해시만으로 원문을 복원하거나 전체 내용을 검증할 수는 없습니다.
- 등록된 발행 내용은 임의로 덮어쓰지 않고, 철회 등 변경은 이력으로 남깁니다.

현재 로컬 EVM은 개발·시연 환경입니다. **공개 체인과 서버 밖 검증은 목표 구조**이며, 구체적인 공개 네트워크와 배포 방식은 아직 정하지 않았습니다. 기관 심사·발행키·등록 경로에 대한 신뢰는 별도로 필요합니다.

### 보호할 항목과 온체인 저장 정보

보호 기준은 **“발행 이후 바뀌면 납부 대상이나 조건이 달라지는 항목”**입니다.

| 서명과 해시로 보호할 항목 | 공개 체인에 저장할 정보 |
| --- | --- |
| 발행기관·요청 식별자 | 기관·키 식별 정보, 발행 공개키, 요청 식별자 |
| 금액·통화, 수취 은행·계좌·예금주, 납부 목적·기한 | 보호된 내용의 해시 또는 서명 대상 digest |
| 발행 시각·유효기간 | 발행 시각·유효기간 |
| 특정 수신자에게 발행하는 경우 수신자 연결 정보 | 필요한 경우 비공개 수신자 정보의 검증용 연결값 |
| 요청·기관·키의 현재 유효성은 별도 상태로 확인 | 요청 철회, 기관 중지, 발행키 폐기 상태와 변경 이력 |

원문·개인정보·인증코드·개인키는 공개 체인에 저장하지 않습니다. 단순 안내 문구와 화면 디자인은 보호 대상에서 제외할 수 있으며, 제외한 부분까지 내용 일치를 보장하지 않습니다.

보호 항목을 수정해야 하면 **기존 요청을 철회하고 새 요청을 발행**합니다. 실제 결제 확인과 연결하지 않은 납부 완료는 기록하지 않습니다.

### 기관 인증 절차 — 가상 정보로 시연

**실제 국세청 API를 호출하지 않고**, 사전에 준비한 가상 기관 명부와 대조합니다. 명부에는 기관명·테스트용 사업자번호·대표자명·개업일자·기관 상태·공식 이메일 도메인·기관 승인 담당자 계정을 준비합니다. 신청자가 이 명부를 임의로 수정할 수 없게 합니다.

| 순서 | 절차 | 통과 조건 |
| --- | --- | --- |
| 1 | 기관정보 확인 | 사업자번호·기관명·대표자명·개업일자가 명부와 일치하고 기관이 정상 상태 |
| 2 | 업무용 이메일 인증 | 등록된 기관 도메인의 이메일과 인증코드 확인 |
| 3 | 발행 권한 신청 | 납부 요청 발행 담당자 권한을 신청하고 승인 대기 |
| 4 | 기관 내부 승인 | 명부에 미리 지정된 기관 승인 담당자가 별도 계정으로 승인 |
| 5 | 서비스 운영자 승인 | 앞선 확인과 기관 내부 승인을 검토하고 최종 승인 |
| 6 | 권한 활성화·키 등록 | 승인된 담당자에게 자기 기관의 발행·키 등록 권한을 부여하고 발행키 연결 |

이메일 인증만으로 자동 승인하지 않습니다. 기관 내부 승인자는 신청자가 임의로 지정할 수 없고, 자기 신청과 다른 기관의 신청은 승인할 수 없습니다.

실제 이메일 대신 **데모용 메일함**에서 인증코드를 확인합니다. 코드의 만료·재사용 금지·입력 횟수 제한은 실제로 동작하도록 설계합니다. 승인 후에도 온체인 기관 활성화까지 확인해야 발행을 허용합니다.

가상 명부는 기관정보 조회를 모의하는 용도이며, 실제 사업자의 실체를 인증한 것으로 설명하지 않습니다.

### 요청마다 수행할 등록 전 검증

**담당자 소속·발행 권한 확인 → 기관·계정·발행키의 유효성 확인 → 필수 입력·기간 검사 및 내용 확정 → 기관 서명 → 서명·해시·기관 및 키 연결 검증 → 체인 등록 → 성공과 등록 상태 확인**

검증을 통과한 발행 사실만 기록하는 것이 목표입니다. 가입 승인 후에도 매 요청의 권한과 현재 상태를 확인합니다. 서버와 체인에서 무권한 등록을 차단하고, 대기·실패·미확인 작업은 성공으로 표시하지 않습니다.

시연은 다음 결과를 보여주는 방향입니다. 아직 실행한 검사 결과는 아닙니다.

| 사례 | 기대 결과 |
| --- | --- |
| 없는 사업자번호·기관정보 불일치·이메일 및 코드 오류 | 해당 확인 단계에서 거부 |
| 승인 누락·자기 신청 승인·타 기관 승인·권한 회수·기관 중지·키 폐기 | 승인 또는 발행 거부 |
| 모든 검증을 통과한 정상 발행 | 체인 반영 확인 후 등록 완료 |
| 수신한 요청의 금액·계좌 변경 | 보호 항목 불일치 표시 |
| 철회·만료 | 현재 사용 불가 표시 |
| 발행 기록 없음 | 발행 사실 확인 불가로 표시하며 피싱으로 확정하지 않음 |

기존 [개발 계획서](development_plan.md)와 [ADR 0001](adr/0001-finals-contracts.md)에 새 인증 단계·공개 체인·별도 검증 방향을 후속 반영해야 합니다. 관련 영역은 W1 기관 신청·권한, W2 기관 활성화·키, W3 발행·검증, W4 상태 관리입니다. 이 문서 자체는 기존 계약이나 구현을 변경하지 않습니다.

## 2. AI로 어떤 부분을 판단할 것인가

**정한 방향:** AI는 사용자 입력의 초반에서 피싱 패턴과 유형을 분석합니다. 블록체인에 등록된 자료인지와 무관하게 분석하고, 의심되는 부분과 그 이유를 설명합니다.

### 입력 범위와 처리 방식

이번 시연에서는 **텍스트·녹음 파일·문서 및 이미지 세 가지를 모두 지원**하는 것으로 정했습니다.

| 입력 | 처리 방식 | 근거 위치 |
| --- | --- | --- |
| 문자·메신저·대화 내역 | 붙여 넣은 텍스트 분석 | 원문 문장 |
| 녹음 파일 | 음성을 텍스트로 변환한 뒤 대화 내용 분석 | 해당 음성 시간대 |
| 문서·캡처 이미지 | 글자를 추출한 뒤 내용 분석 | 문서 페이지·이미지 내 해당 부분 |

입력을 텍스트로 정리하여 공통 기준으로 분석하되, 의심 근거를 원래 입력의 위치와 연결합니다. 읽거나 듣지 못한 부분은 추측해서 채우지 않고 분석이 제한된 부분을 표시합니다.

### 탐지 항목

| 탐지 항목 | 분석 내용 |
| --- | --- |
| 기관·인물 사칭 정황 | 은행·수사기관·가족 등을 내세워 특정 행동을 요구하는 맥락 |
| 긴급성·불안 조성 | 즉시 송금하지 않으면 계좌 정지 등 불이익이 발생한다고 압박하는 표현 |
| 송금·계좌 변경 유도 | 송금을 유도하거나 제공된 기존 안내와 다른 계좌를 요구하는 정황 |
| 민감정보 요구 | 비밀번호·인증번호·보안카드 정보 등의 요구 |
| 링크·앱 설치 유도 | 링크 접속이나 원격제어 앱 설치 등의 요구 |
| 확인 방해·비밀 유지 요구 | 주변에 알리지 못하게 하거나 전화를 끊지 못하게 하는 정황 |

단어의 등장 여부만으로 판단하지 않고 **요구 행동과 대화 맥락을 함께 분석**합니다. 비교할 기존 안내가 없으면 계좌가 실제로 변경되었다고 단정하지 않습니다.

### 판단 결과

피싱 확률을 임의의 백분율로 표시하지 않고, 다음 네 가지 결과와 근거를 제공합니다.

| 결과 | 의미 |
| --- | --- |
| 위험 높음 | 송금·정보 탈취 등으로 이어질 수 있는 강한 의심 정황이 발견됨 |
| 주의 필요 | 의심 요소가 있으나 추가 확인이 필요함 |
| 뚜렷한 의심 정황 없음 | 제공된 내용에서 주요 의심 패턴이 발견되지 않음 |
| 판단 보류 | 내용이 부족하거나 음성·문서 인식이 불완전하여 판단하기 어려움 |

‘뚜렷한 의심 정황 없음’은 안전을 보증하는 표현으로 사용하지 않습니다. 분석 범위와 인식 한계를 결과에 함께 표시합니다.

### 보고서 구성

1. **한 줄 결과:** 위험 수준과 핵심 이유를 설명합니다.
2. **의심되는 원문:** 해당 문장과 원문·음성·문서 내 위치를 표시합니다.
3. **의심하는 이유:** 어떤 요구와 패턴 때문에 의심하는지 설명합니다.
4. **의심 유형:** 기관 사칭형·송금 유도형·개인정보 탈취형 등을 표시합니다.
5. **확인할 행동:** 공식 연락처로 발행 여부 확인 등 상황에 맞는 행동을 안내합니다.

최종 보고서에는 **AI가 의심한 근거와 실제 발행 기록 검증 결과를 각각 유지**합니다. AI가 위험을 낮게 판단하더라도 확인 가능한 발행 기록은 대조합니다. AI 판단을 기관 인증이나 온체인 등록 승인 근거로 사용하지 않습니다.

기존 AI 필드 추출 계획에서 피싱 위험 분석으로 역할을 확대하는 후속 구현이 필요합니다. 지원 파일 확장자·크기·녹음 길이, 사용할 모델과 성능 평가 기준은 구현 단계에서 구체화할 사항이며 이번 결정으로 확정한 값은 없습니다.

## 3. 일반 DB와 블록체인을 어떻게 함께 사용할 것인가

**정한 방향:** 일반 DB에 원본과 분석 자료를 보관하고, 블록체인에 등록된 발행 증거·상태와 대조합니다. 두 저장소는 **납부 요청 식별자**로 연결합니다.

### 저장 정보 분담

| 정보 | 저장 위치 | 목적 |
| --- | --- | --- |
| 기관 명부·계정·소속·발행 권한·신청 및 승인 이력 | 일반 DB | 기관 인증과 발행 권한 확인 |
| 기관이 발행한 납부 요청 원본·전자서명 | 일반 DB | 사용자가 받은 내용과 비교하고 별도 검증 자료로 제공 |
| 기관·키 정보, 요청 식별자·해시·기간·철회 상태 | 블록체인 | 발행 증거와 현재 유효성 확인 |
| 비공개 수신자 정보와 서버 전용 연결 정보 | 일반 DB 등 보호된 체인 밖 저장소 | 수신자 권한 확인. 체인에는 필요한 검증용 연결값만 기록 |
| 사용자가 제출한 문자·녹음·문서와 추출한 텍스트 | 체인 밖 임시 저장소·DB | AI 분석과 내용 비교 |
| AI 분석 결과·의심 근거·최종 보고서 | 일반 DB | 결과 제공 및 사용자가 선택한 보고서 보관 |
| 체인 등록 작업의 진행·실패 이력 | 일반 DB | 등록 상태 확인과 실패 처리 |

파일은 파일 저장소에 두고 DB에는 위치와 관련 정보를 보관할 수 있습니다. **기관의 발행 개인키는 별도의 보호된 키 저장소에서 관리**합니다.

### 기관이 납부 요청을 발행할 때

**요청 작성 → 권한 확인·내용 확정·서명 및 등록 전 검증 → DB에 원본·서명 저장 → 블록체인에 발행 증거 등록 → 등록 완료 확인**

DB 원본과 온체인 기록에 같은 납부 요청 식별자를 연결합니다. 실제 온체인 식별자는 계약에 따라 해당 식별자의 해시 등으로 표현할 수 있으며, 동일 요청을 찾는 대응 규칙을 유지합니다.

DB 원본의 보호 항목으로 해시를 다시 계산하여 체인 기록과 대조합니다. 금액이나 수취 계좌가 발행 이후 바뀌면 불일치를 확인할 수 있습니다. 해시만으로 삭제된 원본을 복원할 수는 없습니다.

DB에 저장됐어도 체인 반영이 확인되기 전까지는 **등록 대기**입니다. 실패하면 실패 상태를 남기고, 결과가 불확실하면 기존 트랜잭션과 등록 상태를 먼저 확인한 뒤 처리합니다. DB 저장만으로 등록 성공을 표시하거나 미확인 거래를 무조건 재전송하지 않습니다.

### 사용자가 의심 자료를 제출할 때

**자료 제출 → 텍스트 추출·AI 분석 → 요청 식별자 확인 → DB 원본·서명 및 체인 기록 조회 → 내용·현재 유효성 검증 → 통합 보고서**

| 사용하는 정보 | 확인하는 내용 |
| --- | --- |
| 사용자 입력 | 사용자가 실제로 받은 내용 |
| AI 분석 | 의심스러운 표현·요구·맥락과 그 근거 |
| DB 원본·서명 | 기관이 발행한 보호 항목과 수신 자료의 일치 여부 |
| 체인 기록 | 원본 해시, 발행기관·키, 철회·만료 등 현재 상태 |

요청 식별자는 자료의 ID·QR·검증 링크 등에서 찾습니다. 연결할 기록을 찾지 못하면 **AI 분석은 제공하고, 발행 기록 검증은 ‘확인 불가’**로 표시합니다. 음성·문서에서 식별자나 금액을 제대로 읽지 못한 경우 사용자 확인을 받거나 판단을 보류합니다.

사용자 제출 자료와 AI 판단은 기관의 발행 사실로 취급하지 않으며, 자동으로 블록체인에 등록하지 않습니다. 최종 보고서에서도 AI 판단과 발행 기록 검증 결과를 각각 표시합니다.

### 보관과 상태 관리 기준

| 대상 | 정한 원칙 |
| --- | --- |
| 현재 유효성 | 체인의 상태를 기준으로 확인합니다. DB의 상태 사본은 조회 편의를 위해 사용합니다. |
| 체인 조회 실패 | 마지막으로 저장된 값만으로 현재도 유효하다고 판단하지 않고 확인을 보류합니다. |
| 사용자 제출 파일·분석용 입력 | 분석과 보고서 제공에 필요한 동안 임시 보관하고 처리 종료 후 삭제하는 것을 기본으로 합니다. |
| 보고서 보관 | 사용자가 저장을 선택한 경우 분석 결과와 필요한 근거를 보관합니다. 원본 파일 저장은 별도로 선택하게 합니다. |
| 기관 발행 원본·서명 | 재검증에 필요하므로 사용자 제출 파일과 별도로 보관합니다. |

**구현 단계에서 구체화할 사항:** 정확한 보존 기간과 임시 자료의 삭제 시점, 상태 동기화·재처리의 세부 방식, 저장 모델과 API. 멘토링에서 설명할 저장 분담과 처리 원칙은 정리되었으며, 이 문서는 해당 기능의 구현 완료를 의미하지 않습니다.
