# M3 — 스마트 계약 코어

> **MVP 과거 기록 — 현재 작업 지시로 사용하지 마세요.** 당시 역할·브랜치·미완료 상태·설정값을 보존한 문서입니다. 현재 개발은 [시작 안내](../../START_HERE.md)와 [개발 계획서](../development_plan.md)를 따르며, 아래의 실행/병합 지시는 자동으로 적용하지 않습니다.

기관과 서명 키의 **등록 여부·상태·유효 기간**을 온체인에서 관리합니다.
증명 원문을 저장하거나 최종 `VERIFIED` 판정을 내리는 역할은 아닙니다.

## 담당 파일과 동작 순서

1. `packages/contracts/src/IssuerRegistry.sol`: 기관을 등록하고 중지·재활성화·폐기합니다.
2. `packages/contracts/src/IssuerKeyRegistry.sol`: 기관의 공개 signer와 키 유효 기간을 등록합니다.
3. 조회 시 기관 ACTIVE, 키 ACTIVE, `validFrom <= 시각 < validUntil`을 함께 확인합니다.
4. 상태 변경 이벤트를 남깁니다. 폐기된 기관·키는 되돌리지 않습니다.

문자열 식별자는 `keccak256(utf8(ID))`로 변환합니다. 카드 정보·증명 원문·개인키는
온체인에 넣지 않습니다. API와의 변환·배포는 [M4 문서](M4_README.md)를 참고하세요.

## 검증

저장소 루트에서 다음 명령을 실행합니다. 이 명령은 고정 Foundry 컨테이너를 사용하므로
MVP 재현에는 호스트 Foundry 설치가 필요하지 않습니다.

```bash
make test-contracts
```

권한 없는 호출, 중복·0 주소, 상태 전이, 키 기간 경계 등을 검사합니다.
이번 작업은 기존 코어와 M4 호출의 호환성을 검증했으며 계약 소스·테스트를 변경하지 않았습니다.
따라서 이번 작업으로 인한 계약 인터페이스 변경이나 기존 배포 마이그레이션은 없습니다.
